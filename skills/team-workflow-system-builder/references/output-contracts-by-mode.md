# Output Contracts By Mode

Use the smallest output that resolves the selected action.

## Contents

1. Repository audit
2. Guided start
3. System build
4. Repair implementation
5. Template pack

8. Skill packaging and composite iteration

## Repository Audit

Produce:

1. One-line health conclusion.
2. Scope and evidence reviewed.
3. Current digitization profile, adoption evidence, and one evidence-backed AS-IS workflow slice.
4. Repository/workspace/runtime topology.
5. Findings ordered by P0/P1/P2 with file evidence, separating workflow fidelity, online governance, and AI runtime.
6. Safe fix sequence, specialist handoffs, and what not to change.
7. Unresolved business decisions, warnings, and migration debt.

Do not implement fixes unless write authority was also given.

## Guided Start

Produce only the current progressive artifact:

- Transformation boundary.
- One provisional AS-IS workflow slice.
- Accepted rules versus unresolved decisions.
- Current and target digitization profile plus adoption evidence.
- The next reversible output or material-reading boundary.

Ask at most 1-2 questions for the next step.

## System Build

Produce:

- Existing-work baseline, assumptions, unresolved decisions, and exclusions.
- Current and target digitization profile plus adoption evidence.
- AS-IS workflow and preserved semantics.
- TO-BE online object/state/action/authority/artifact model.
- Human-only and AI-eligible work boundaries.
- Specialist implementation handoffs and integration contract.
- Minimum workspace, governance, runtime, and migration assets for the selected slice.
- Smallest real pilot and acceptance evidence.

Use `system-output-template.md` only when a full formal report is requested.

## Repair Implementation

Produce or update:

- Repair contract and baseline.
- Preserved workflow semantics, target digitization profile, and unresolved business rules.
- Migration record and rollback point.
- Contract, navigation, registry, templates, and scoped project files.
- Validation output.
- For AI-maintained systems, runtime activation evidence from the real working directory: applicable entrypoint, installed capability source, pre-write result, and post-write result.
- Clean/dirty state and remaining warnings.
- Human decisions that remain pending.
- Specialist handoffs and whether each output has been reintegrated.

Do not modify business/project content outside the accepted repair scope.

## Template Pack

Deliver copy-ready files plus:

- System/template/contract version.
- Canonical runtime template location.
- Template manifest.
- Field adaptation notes.
- Validation command.
- Migration rule.

Do not return only a list of template names.

## Role Redesign

Produce:

- Result-owning role slots.
- Responsibility and decision-right matrix.
- Merge/separation rules for light versus complex projects.
- Handoff and escalation rules.
- Named organizational questions that remain unresolved.

## Material Organization

Produce:

- Objective, allowed scope, output, and exclusions.
- Source classification and evidence limits.
- Organized structure with fact/claim/assumption labels.
- Unread or unresolved materials.

## Skill Packaging

Produce:

- Workflow capability boundary, accepted inputs/outputs, allowed actions, human decisions, runtime assumptions, and eval requirements.
- A handoff to a dedicated Skill-packaging capability when available.
- When this Skill is explicitly responsible for packaging: lean `SKILL.md`, only required resources, `agents/openai.yaml`, validation, realistic evals, installation/discovery evidence, and a real-entrypoint forward test.

Do not package a workflow that has not reached at least `online-tested`; label non-adopted workflow Skills as provisional.

## Composite Audit, Repair, And Skill Iteration

When the user explicitly requests all phases, deliver one traceable chain:

1. Audit evidence and prioritized control-plane findings.
2. Baseline, repair contract, migration, scoped repository changes, and validation.
3. Skill changes mapped to observed failure modes, updated scripts/references/evals, and Skill validation.

Do not let the Skill update obscure unresolved repository warnings or imply that project-level migration was completed.
