# Zero-To-One Progressive Digitization Flow

Use this reference when the workflow baseline or target digitization profile is unclear. Do not use it to block an explicit read-only audit or restart an accepted continuation.

## Contents

1. Interaction principle
2. Progressive sequence
3. Guided-mode exclusions

## 1. Interaction Principle

Ask only the next one or two questions that materially change the digital operating model. At each step:

1. Use the team’s language.
2. Separate observed practice, written rules, unresolved decisions, and AI assumptions.
3. Produce a provisional AS-IS or TO-BE fragment for correction.
4. Do not ask the team to design the whole system before it can react to anything concrete.

If the next high-value question remains unclear, use `discovery-question-pack.md` as a menu and select only one or two relevant prompts.

## 2. Progressive Sequence

### Step 1: Confirm The Work Boundary

Identify:

- the work being digitized;
- typical work object or project;
- participants and decision owner;
- start and end boundary;
- current tools/materials;
- requested target: documentation, structure, local/shared/platform operation, governance, AI assistance, or AI execution.

Do not broaden a workflow-digitization request into business strategy or organization redesign.

### Step 2: Recover One Real AS-IS Case

Ask for one recent representative case, not an idealized SOP. Map:

```text
trigger
  -> actor
  -> action
  -> input/source
  -> output
  -> state change
  -> review/decision
  -> exception/rework
```

Record where actual practice differs from documentation. Do not normalize the difference before its meaning is understood.

### Step 3: Separate Rules From Decisions Still Owed

Classify each important statement as:

- accepted business rule;
- actual but unofficial practice;
- historical accident;
- unresolved decision;
- proposed digital mechanism.

The Skill may structure an accepted rule. It may not convert an unresolved decision into a default merely to complete the workflow.

### Step 4: Choose The Smallest Profile Change

Select only the dimensions needed by the request:

- representation: tacit/manual -> documented -> structured;
- execution surface: local -> shared repository/toolspace/platform when collaboration requires it;
- governance: unmanaged -> controlled -> governed;
- AI coverage: none -> assisted or executable for named work items only;
- adoption evidence: designed -> online-tested -> pilot-adopted -> operationally-accepted.

State which working dimensions are preserved and what this slice will not solve. Do not force a governed local workflow through a shared-platform migration merely to move along a maturity ladder.

### Step 5: Define Digital Objects And Human Boundaries

Identify only what the selected slice needs:

- work object and lifecycle state;
- actor, owner, reviewer, decision right;
- source, artifact, version, and evidence;
- operation, Gate, approval requirement/result/source, exception, and recovery;
- AI-eligible work and human-only decisions.

### Step 6: Confirm First Output And Material Boundary

Choose the first useful output:

- AS-IS map;
- digital operating-model blueprint;
- minimum project/workspace implementation;
- AI-node design and eval;
- repository repair;
- migration/pilot plan.

If materials are needed, confirm approved sources, excluded sources, no-edit range, confidentiality, and reuse limits.

### Step 7: Exit Guided Mode

Exit when the work boundary, one real case, accepted/unresolved rules, current and target digitization profile, first output, and material boundary are clear enough for a reversible next step.

Do not demand perfect certainty. Keep unknown business rules visible and proceed only where later correction is safe.

## 3. What Guided Mode Must Not Produce

- a complete governance system before a real AS-IS case is understood;
- a fixed template pack for every future stage;
- invented approval, ownership, policy, or acceptance rules;
- custom software architecture without a specialist handoff;
- AI execution before the digital work object and human authority are stable.
